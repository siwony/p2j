이 기획서는 집안일과 공부를 주간 단위로 계획하고 실행하도록 돕는 iOS 앱의 첫 버전 개발 범위를 정의한다. 첫 버전은 iPhone에 집중하고, Mac 앱 지원은 다음 단계로 확장한다. 사용자가 자신의 생활에 맞는 루틴을 찾아가고, 계획이 흐트러진 뒤에도 부담 없이 다시 시작할 수 있는 경험을 목표로 한다.

본 문서의 사용자 문제와 제품 원칙은 기획 의뢰자의 실제 경험과 대화에서 확인한 요구를 기반으로 한다. 개발 일정, 예산, 검증 목표는 실행을 위한 제안이며 확정된 견적이나 검증 결과가 아니다.

# Why 배경과 현황

## 기획 배경

기획 의뢰자는 집안일을 생활 속 루틴으로 만들지 못해 반복해서 미루고 있으며, 공부도 체계적으로 이어가고 싶어 한다. 필요한 일을 적어두는 것에서 더 나아가, 이번 주에 할 수 있는 분량을 고르고 실제로 시작하는 과정까지 연결할 필요가 있다.

사용자가 특히 중요하게 여기는 조건은 앱 사용에서 강박감이나 죄책감을 느끼지 않는 것이다. 완료하지 못한 일이 누적되거나 기록을 유지해야 한다는 부담이 커지면 앱을 계속 사용하기 어려울 수 있다는 우려를 제품 설계에 반영한다.

## 해결할 문제

| 문제 | 사용자에게 필요한 지원 |
| --- | --- |
| 해야 할 일을 계속 미룬다 | 실행할 요일을 고르고 알림에서 바로 시작하는 흐름 |
| 하고 싶은 일을 현실적인 분량으로 정하기 어렵다 | 주간 횟수와 요일별 예상 시간을 보며 계획하는 기능 |
| 집안일과 공부의 실천을 돌아보기 어렵다 | 완료 횟수와 선택적인 시작 및 종료 기록 |
| 계획이 무너지면 다시 시작하기 부담스럽다 | 날짜 변경, 분량 축소, 건너뛰기와 쉬운 재계획 |
| 루틴 계획이 기존 일정과 분리된다 | 이번 주에 선택한 일을 캘린더에 표시하는 기능 |
| 자신에게 맞는 실행 방식을 기억하기 어렵다 | 다음 계획에 참고할 수 있는 짧은 주간 메모 |

이 문서는 시장 규모나 경쟁 앱의 성과를 가정하지 않는다. 첫 단계에서는 본인이 직접 사용하는 환경에서 문제 해결 여부를 확인하고, 다른 사용자에게도 같은 필요가 있는지는 이후 별도로 검증한다.

# What 핵심 아이디어와 목표

## 제품 정의

한 주는 루틴함에 모아둔 일 중 이번 주에 할 일을 선택하고, 요일에 배치한 뒤, 알림과 간단한 기록을 통해 실행을 이어가는 개인용 주간 루틴 보조 앱이다.

핵심 사용 흐름은 **루틴 등록 → 일요일에 다음 주 계획 → 당일 알림과 실행 → 필요할 때 일정 조정 → 짧은 메모 → 다음 주 계획에 반영**이다.

일주일은 월요일부터 일요일까지로 정의한다. 일요일 계획 화면은 진행 중인 이번 주와 계획할 다음 주를 날짜로 구분해 보여준다.

## 대상 사용자와 이용 환경

초기 사용자는 iPhone에서 집안일과 공부를 꾸준히 이어가고 싶은 기획 의뢰자 본인이다. 루틴 등록, 주간 계획, 알림 확인, 실행 기록, 회고까지 모든 과정을 iPhone 한 대에서 마칠 수 있어야 한다. 첫 버전의 화면과 실기기 검증 대상은 iPhone으로 한정한다. Mac 앱과 기기 간 데이터 동기화는 iOS 실사용 검증 이후 다음 단계에서 제공한다.

## 제품 목표

1. 사용자가 이번 주에 가능한 분량을 스스로 정하도록 돕는다.
2. 알림을 받은 뒤 첫 행동을 시작하고 완료를 남기는 과정을 짧게 만든다.
3. 미완료 이후에도 계획을 바꾸거나 다시 시작할 수 있게 한다.
4. 실천 기록과 메모를 통해 자신에게 맞는 시간대와 분량을 발견하도록 돕는다.

## 경험 설계 원칙

| 원칙 | 제품에 반영할 기준 |
| --- | --- |
| 계획은 조정할 수 있다 | 횟수와 요일을 바꾸거나 한 주를 쉬는 선택을 제공한다 |
| 미완료를 빚처럼 쌓지 않는다 | 다음 주 자동 이월과 미완료 개수 배지를 기본으로 사용하지 않는다 |
| 알림은 제안한다 | 무응답을 이유로 알림을 늘리지 않고 사용자가 시간을 조정하게 한다 |
| 기록 부담을 낮춘다 | 타이머 없이 바로 완료할 수 있고 회고를 비워둘 수 있다 |
| 성취는 실제 행동에 근거한다 | 완료한 일과 기록한 시간을 보여주며 미기록 시간을 추정하지 않는다 |
| 쉬어도 누적 성취가 남는다 | 연속 일수와 완료율을 메인 화면의 평가 지표로 삼지 않는다 |

## 첫 버전 범위

첫 버전은 iPhone용 iOS 앱으로 제공한다. 루틴함, 주간 계획, 알림, 실행 기록, 일정 조정, Apple 캘린더 연동, 자유 메모 회고, 간단한 성취 기록과 기기 내 데이터 저장을 포함한다. 첫 실행에서는 권한 요청 없이 빈 오늘 화면에서 루틴 등록과 이번 주 계획으로 이동할 수 있다. 계획은 일요일 외의 요일에도 시작할 수 있다.

다음 단계에서는 Mac 앱과 iPhone 및 Mac 간 데이터 동기화를 개발한다. 캘린더에서 수정한 내용을 앱으로 가져오는 기능, Google Calendar API 직접 연동, 자동 계획 생성, 친구와의 경쟁, 캐릭터 육성, 복잡한 통계와 유료 결제는 별도의 후속 검토 대상으로 둔다. 사업화와 수익모델은 개인 실사용 검증 이후 판단한다.

# How 구체적 실행 방안 일정 예산

## 사용자 흐름과 기능

### 루틴을 모으는 단계

루틴함에는 이름, 분류, 예상 소요 시간을 기본 정보로 저장한다. 이름만 입력해도 등록할 수 있고, 권장 주간 횟수, 선호 요일, 메모, 시작할 때 할 작은 행동은 선택 입력으로 둔다. 등록한 루틴을 보관하거나 수정해도 과거의 실행 기록은 유지한다.

작업명은 한 번에 실행할 수 있는 크기로 적도록 안내한다. 예를 들어 책상 정리하기, SQL 문제 두 개 풀기처럼 완료 기준을 이해할 수 있게 한다. 시작 행동에는 컵부터 치우기, 문제집 펼치기 같은 짧은 안내를 남길 수 있다.

### 일요일에 계획하는 단계

기본 계획 알림은 일요일 오후 8시이며 사용자가 변경하거나 끌 수 있다. 알림을 열면 이번 주의 해낸 일과 메모를 확인한 뒤 다음 주에 할 루틴을 고른다. 회고를 작성하지 않아도 다음 단계로 이동할 수 있다.

지난주 계획을 가져오거나 루틴함에서 직접 선택할 수 있다. 선택한 루틴은 주간 횟수만큼 실행 항목으로 만들어 요일에 배치한다. 시간을 지정하지 않고 요일만 정할 수도 있다. 요일별 예상 소요 시간을 보여주어 과한 계획을 조정하게 한다.

주중에도 계획을 추가하거나 수정할 수 있다. 처음 계획할 때 횟수와 요일을 정하고, 이미 계획한 주에서는 기존 회차가 보이는 상태에서 필요한 회차만 추가한다. 줄일 때는 원하는 회차를 건너뛰며 완료 기록을 삭제하지 않는다. 지난 계획 가져오기는 후보를 채우는 기능이고, 확정 전에는 실행 항목을 만들지 않는다.

계획이 없는 주에는 ‘이번 주 쉬기’로 비워둘 수 있다. 이미 계획이 있는 주의 일을 이 동작으로 한꺼번에 삭제하지 않는다. 계획이 있는 항목은 개별적으로 옮기거나 건너뛴다. 지난 계획은 자동으로 이월하지 않는다.

### 알림을 받고 실행하는 단계

홈 화면에는 오늘 예정된 일을 보여준다. 시간 지정 항목은 해당 시간에 알림을 제공하고, 요일만 지정한 항목은 사용자가 고른 기본 시간에 묶어서 알린다. 아침 일정 요약은 선택 기능이며 첫 버전의 필수 범위에는 넣지 않는다.

한 항목의 실행 알림은 시작하기와 30분 뒤 다시 알림을 제공한다. 여러 항목을 묶은 알림의 시작하기는 오늘 목록을 열어 실행할 한 가지를 고르게 한다. 여러 일을 동시에 시작하지 않는다.

30분 뒤 다시 알림은 사용자가 요청한 알림만 미룬다. 자정을 넘어가도 계획 날짜는 바뀌지 않는다. 날짜 변경·완료·건너뛰기 이후에는 관련된 기본 알림과 다시 알림을 정리하고 묶음 알림의 남은 항목을 갱신한다. 이미 지난 알림은 자동으로 몰아서 재발송하지 않는다.

알림 예시는 “오늘 책상 정리 10분, 지금 시작할까요?”처럼 제안하는 말투를 사용한다. 응답하지 않아도 자동으로 재촉하지 않는다. 첫 버전의 알림은 iPhone에서 제공하며, 사용자가 계획 알림과 실행 알림을 각각 켜거나 끌 수 있게 한다.

### 실행을 기록하는 단계

기본 흐름은 시작, 일시 정지, 이어서 하기, 완료다. 시작과 종료 시각을 남기고 일시 정지 시간을 제외한 소요 시간을 계산한다. 종료를 잊은 경우 기록을 수정할 수 있다.

이미 끝낸 일은 “이미 했어요”로 바로 완료한다. 타이머 없이 완료한 항목은 시간 미기록으로 표시하며, 사용자가 원할 때 실제 시간을 직접 입력할 수 있다. 실제 기록이 1분 미만이면 “1분 미만 기록”으로 구분한다. 짧게 실행하다 중단한 항목은 진행 기록을 남기고 나중에 이어서 할 수 있다.

동시에 시간을 재는 일은 하나다. 다른 일을 시작하면 하던 일을 일시 정지할지 선택하게 한다. 실행 화면에서 뒤로 가거나 다른 탭으로 이동해도 기록은 계속된다. 완료한 일은 완료 시점의 현지 날짜를 기준으로 기록 화면에 모으고, 원래 계획 날짜는 별도로 유지한다.

### 계획을 조정하는 단계

미완료 항목에는 오늘 나중에 하기, 다른 날로 옮기기, 이번 주 건너뛰기를 제공한다. 이유 입력은 요구하지 않는다. 완료 취소와 잘못 기록한 시간의 수정도 지원한다.

한 주가 끝나면 미완료 항목을 다음 계획의 선택 후보로만 보여준다. 다시 선택하지 않은 일을 다음 주의 밀린 일로 누적하지 않는다. 지난주의 기록은 보관한다. 반복해서 미루는 일의 횟수나 분량을 자동으로 추천하는 기능은 실사용 이후 검토한다.

## 캘린더 연동

주간 계획에서 캘린더 반영을 선택하면 해당 주의 실행 항목만 루틴용 캘린더에 등록한다. 루틴 원본에 무기한 반복 일정을 만들지 않는다.

| 상황 | 연동 규칙 |
| --- | --- |
| 요일만 정한 항목 | 해당 날짜의 종일 일정으로 등록한다 |
| 시간을 정한 항목 | 시작 시각부터 예상 소요 시간만큼 일정으로 등록한다. 예상 시간이 없으면 해당 항목의 시간을 정하도록 안내하고 그 항목은 반영 대기로 남긴다 |
| 앱에서 날짜나 시간을 변경 | 연결된 기존 일정을 수정한다 |
| 이번 주 계획에서 제외하거나 건너뜀 | 앱이 만든 연결 일정을 제거하고 앱의 변경 이력은 남긴다 |
| 실행 완료 | 캘린더의 계획 일정은 유지하고 실제 실행 기록은 앱에 저장한다 |
| 캘린더 반영을 다시 실행 | 기존 연결을 확인해 동일 항목을 중복 생성하지 않는다 |
| 캘린더에서 직접 수정 또는 삭제 | 앱에는 자동 반영하지 않으며, 차이가 확인되면 사용자에게 앱 계획으로 다시 반영할지 선택하게 한다 |

첫 반영은 사용자가 선택한 주에서 명시적으로 시작한다. 연결된 항목의 이후 변경·완료·건너뛰기는 위 규칙에 따라 반영한다. 같은 주에 나중에 새로 추가한 항목은 다음 반영 때 포함한다. 앱 저장이 끝나고 캘린더 작업이 실패한 경우 앱 계획은 유지하며 반영 대기와 재시도만 표시한다. 일부 항목의 오류 때문에 다른 정상 항목을 취소하지 않는다.

첫 버전의 연동 방향은 iPhone 앱에서 Apple 캘린더로 정한다. 사용자가 선택한 쓰기 가능한 루틴용 캘린더에 일정을 반영하고, 실행 항목과 캘린더 일정의 연결 정보를 기기에 저장해 반복 반영 시 중복을 방지한다. 실패한 반영은 상태를 표시하고 다시 시도할 수 있게 한다. 캘린더 계정 자체의 동기화는 운영체제 설정을 따르며, 앱의 루틴과 메모를 다른 기기로 동기화하는 기능은 Mac 지원 단계에서 다룬다.

캘린더 일정의 알림은 기본으로 끄고 앱 알림을 사용한다. 회고 메모와 실제 실행 시간은 캘린더에 내보내지 않는다. 캘린더 연동을 사용하지 않아도 주간 계획과 실행 기능을 사용할 수 있다.

EventKit으로 기존 일정을 읽고 자동 수정하려면 캘린더 전체 접근 권한이 필요하다. 연동을 켤 때 용도를 설명하고 권한을 요청하며, 앱이 만든 루틴 일정만 관리한다. [Apple 캘린더 접근 문서](https://developer.apple.com/documentation/eventkit/accessing-the-event-store)

## 메모 회고와 성취 기록

회고는 주별 자유 메모 입력창 하나로 제공한다. “이번 주에 기억해두고 싶은 게 있나요?”라는 안내를 표시하고 글자 수, 필수 질문, 작성 횟수를 요구하지 않는다. 주중이나 주말에 언제든 작성하고 수정할 수 있으며 자동 저장한다.

예를 들어 “퇴근 후 공부는 힘들었다. 다음 주에는 점심에 10분씩 해봐야겠다”라고 적을 수 있다. 다음 주 계획 화면에서 이전 메모를 함께 보여주어 시간대와 분량을 조정하는 데 참고하게 한다. 회고 작성만을 위한 별도 알림은 두지 않는다.

성취 화면에는 완료한 일, 루틴별 실천 횟수, 기록한 공부 시간, 미룬 뒤 실행을 마친 일을 보여준다. 미기록 시간은 0분으로 단정하지 않고 미기록으로 구분한다. 계획에서 제외한 항목이나 건너뛴 일을 완료로 계산하지 않는다.

주간 전체 완료율과 연속 일수는 메인 화면에 배치하지 않는다. 쉬었다 돌아와도 누적 실천 기록이 유지되도록 한다. 첫 버전에서는 복잡한 배지와 보상 체계보다 실제로 해낸 일을 짧게 확인할 수 있는 경험에 집중한다.

| 화면 | 주요 내용 |
| --- | --- |
| 오늘 | 예정된 일, 시작 및 완료, 일시 정지, 일정 변경 |
| 이번 주 | 월요일부터 일요일까지의 배치, 횟수, 예상 시간, 캘린더 반영 상태 |
| 루틴함 | 할 일 등록, 분류, 수정, 보관 |
| 기록 | 주별 완료 항목, 실천 횟수, 기록한 시간, 자유 메모 |
| 설정 | 주간 계획 알림, 기본 실행 알림 시간, 알림 켜기와 끄기, 캘린더 연결 |

첫 버전은 iPhone 화면에서 오늘 할 일과 실행 버튼에 쉽게 접근하도록 구성한다. 주간 계획도 모바일 화면에서 요일을 선택하고 항목을 옮기는 방식으로 완결한다. Mac 전용 화면과 입력 방식은 후속 단계에서 설계한다.

## 구현 방안과 검증 항목

제안 기술 구성은 SwiftUI 기반의 iPhone용 iOS 앱, SwiftData 기반 로컬 저장, UserNotifications 기반 예약 알림, EventKit 기반 캘린더 연동이다. 첫 버전은 단일 iPhone에서 동작하는 구조로 구현한다. 최소 지원 iOS 버전은 보유한 iPhone의 운영체제와 필요한 API를 확인해 착수 시 확정한다.

앱이 실행 중이지 않아도 시스템이 예약 조건에 따라 로컬 알림을 처리할 수 있으므로, 루틴 알림 발송을 위한 별도 서버는 첫 버전에 두지 않는다. 알림 권한이 없을 때도 앱에서 오늘 할 일을 확인하고 완료할 수 있게 한다. [Apple 로컬 알림 문서](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)

앱의 데이터는 루틴 원본, 주간 계획, 각 회차의 실행 항목, 실행 기록, 주간 메모, 캘린더 연결 정보로 구분한다. 루틴을 수정해도 과거 기록이 변하지 않도록 실행 당시의 정보를 보관한다. 첫 버전의 앱 데이터는 기기에 저장하며, 인터넷 연결 없이도 루틴 조회, 계획 수정, 실행 기록과 메모 작성을 할 수 있게 한다.

CloudKit 기반 앱 데이터 동기화는 Mac 지원 단계에서 도입을 검토한다. 해당 단계에서 기존 iPhone 기록의 이전, 오프라인 변경 충돌과 동기화 지연을 검증한다. 첫 버전에서는 데이터 구조를 명확히 구분하되, 동기화 전용 처리나 Mac용 화면을 미리 구현하지 않는다.

### 날짜와 데이터 보존 기준

계획의 날짜와 시각은 현재 기기 시간대의 생활 시각을 따른다. 시간대가 바뀌면 앞으로 예정된 알림과 연결 일정을 다시 계산하되, 실제로 실행한 시간과 과거 완료 날짜는 바꾸지 않는다. 존재하지 않거나 중복되는 현지 시각은 시스템이 선택한 시각을 표시해 조정할 수 있게 한다. 앱이 종료되어 시스템 변경을 처리하지 못한 동안의 즉시 갱신은 보장하지 않으며, 다음 실행·복귀 또는 시간대 변경 통지 수신 때 미래 알림과 연결 일정을 재조정한다.

루틴은 삭제 대신 보관하고 복원할 수 있다. 앱 자체의 백업·파일 내보내기·다른 기기 복원은 첫 버전에 포함하지 않는다. 앱 삭제나 기기 분실 후 복원을 앱 기능으로 보장하지 않으며, 운영체제 백업은 사용자 설정을 따른다.

2026-10-04 개발 착수: 사용자가 iPhone 15 Pro를 기준으로 기술 선택을 위임했다. 최소 iOS 17·Swift 6·네이티브 SwiftUI/SwiftData, 개인 기기 우선 검증을 [기술 결정](adr/0001-native-ios-foundation.md)에 기록했다. 실제 기기 OS·서명은 연결 단계에서 확인하며, 개발 일정은 기반 검증 후 재산정한다. 다음 표는 확인 책임을 정리한다.

## 개발 일정

아래는 SwiftUI 기본 개발 경험이 있는 1인이 주당 12~16시간을 투입하는 개인 개발 추정안이다. 개발팀에 의뢰할 때의 확정 일정이나 견적은 아니며, 착수 후 다시 산정한다. iOS 첫 버전의 기본 기간은 개발 및 검증 6주와 실사용 2주를 합친 8주, 총 투입은 96~128시간으로 잡는다. 최초 1주 기술 검증 결과에 따라 다시 산정하며, 필요하면 2주의 일정 여유를 추가한다. Mac 앱 개발, 기기 간 데이터 동기화와 외부 배포 심사 기간은 이 일정에 포함하지 않는다.

| 기간 | 실행 내용 | 완료 기준 |
| --- | --- | --- |
| 1주차 | iPhone 화면 흐름과 데이터 구조 정리, 로컬 저장과 캘린더 연동 기술 검증 | 핵심 데이터와 권한 및 연동 방식 확정 |
| 2~3주차 | 루틴함, 주간 선택, 요일 배치, 오늘 화면 구현 | iPhone에서 주간 계획을 만들고 수정할 수 있음 |
| 4주차 | 예약 알림, 시작과 종료, 일시 정지, 바로 완료, 일정 조정 구현 | 계획에서 실행과 기록까지 한 흐름으로 작동 |
| 5주차 | 캘린더 등록, 수정, 제거, 중복 방지와 반영 상태 구현 | 일정을 반복 반영해도 연결 관계 유지 |
| 6주차 | 주간 메모, 성취 기록, 설정과 접근성 보완, 권한과 오프라인 및 저장 종합 검증 | 필수 기능 연결 완료 및 데이터 유실과 중복 등 핵심 결함 해결 |
| 7~8주차 | 집안일 두 개와 공부 한 개로 2주 실사용, 불편 수정 | 사용 부담과 실행 편의를 평가하고 Mac 지원 단계의 요구 정리 |

집안일 두 개와 공부 한 개는 초기 검증을 위한 예시 구성이며, 제품이 사용자에게 강제하는 최소 루틴 수가 아니다. 학습이 필요한 기술이나 연동 문제가 확인되면 일정 여유를 사용하고 기능을 누락한 상태를 완료로 처리하지 않는다.

## 예산과 운영 가정

예산은 보유한 Mac을 개발 장비로, iPhone을 실행 및 테스트 기기로 사용하는 iOS 첫 버전을 기준으로 한다. Mac 앱 개발 비용은 다음 단계에서 별도로 산정한다. 장비 구매, 외주, 마케팅, 추가 유료 개발 도구는 포함하지 않는다. 아래 원화 금액은 지출 계획을 위한 편성액이며 견적 또는 환율 환산액이 아니다.

| 항목 | 편성액 | 산정 근거 |
| --- | --- | --- |
| Apple Developer Program | 연간 200,000원 | 가입 비용을 위한 잠정 편성액. 실제 결제 금액은 가입 시 확인 |
| 개발 및 디자인 도구 | 추가 현금 지출 0원 | Xcode와 기본 UI 구성요소, 보유 도구 사용 가정 |
| 별도 서버 및 유료 API | 추가 현금 지출 0원 가정 | 기기 내 저장과 로컬 알림 및 EventKit 기반의 개인 테스트 구조 |
| 예비비 | 50,000원 | 소액 부대비용과 편성 차이를 위한 여유 |
| 총 현금 예산 | 250,000원 | iOS 초기 개발과 2주 검증을 위한 제안 예산 |
| 개발 시간 | 96~128시간 | 현금 예산과 별도로 관리하는 본인 투입 시간 |

지역별 가입 비용은 [Apple 멤버십 안내](https://developer.apple.com/help/account/membership/program-enrollment)에서 확인한다. 이미 유효한 멤버십이 있다면 해당 비용은 추가 지출에서 제외할 수 있다. 이 경우 본 기획의 추가 현금 편성액은 예비비 50,000원이다.

총 현금 예산 250,000원은 멤버십과 예비비 중심의 개인 개발 부대비용이며 개발 인건비가 아니다. 개발팀에 의뢰할 때는 기능 범위와 투입량에 따른 별도 견적을 받는다.

# So What 기대 효과

## 사용자에게 제공할 가치

| 기대 가치 | 기대하는 변화 | 확인 방법 |
| --- | --- | --- |
| 실행을 시작하기 쉬워짐 | 할 일을 떠올리는 단계에서 구체적인 첫 행동으로 이동 | 사용 전후의 시작 어려움과 실제 실행 사례를 메모로 비교 |
| 생활에 맞는 계획을 세움 | 가능한 횟수와 시간대를 조정하면서 무리한 계획을 줄임 | 주간 계획 수정 이유와 예상 시간 대비 실제 경험 확인 |
| 다시 시작하기 쉬워짐 | 미완료가 생겨도 부담 없이 재배치하거나 다음 주를 선택 | 일정 변경 후 재실행 사례와 복귀 시 느끼는 부담 확인 |
| 성취를 확인할 수 있음 | 집안일과 공부에서 실제로 해낸 행동을 인식 | 주간 기록이 유용했는지 짧은 사용 소감 확인 |
| 계획과 일상 일정이 연결됨 | 루틴을 기존 약속과 함께 보고 실행 시간을 가늠 | 캘린더를 보며 날짜를 조정한 사례 확인 |
| 자기 이해가 쌓임 | 어떤 분량과 시간대가 편한지 메모를 통해 발견 | 이전 메모를 다음 주 계획에 참고한 사례 확인 |

위 효과는 제품 가설이다. 현재 검증된 결과나 모든 사용자에게 보장되는 효과로 해석하지 않는다.

## 초기 성공 판단 기준

아래 기준은 개발자가 첫 버전의 품질과 부담을 점검하기 위한 제안이다. 사용자에게 매일 달성해야 할 점수나 연속 사용 목표로 노출하지 않는다.

| 검증 항목 | 초기 판단 기준 |
| --- | --- |
| 계획의 간편함 | 초기 설정 이후 주간 계획을 대체로 3분 안에 마칠 수 있는지 확인 |
| 기록의 간편함 | 오늘 화면에서 시작 또는 바로 완료를 한 번의 동작으로 처리 |
| 사용 부담 | 2주 종료 시 기록과 알림이 부담스러웠던 상황을 확인하고 우선 개선 |
| 재시작의 용이성 | 자연스럽게 미루거나 쉰 일이 발생하면 재배치와 복귀 과정 확인. 사례가 없으면 판단 유보 |
| 메모의 활용성 | 실제 작성한 메모가 있다면 다음 계획에 참고하기 쉬웠는지 확인. 미작성은 실패로 보지 않음 |
| 기능 신뢰성 | 검증 시나리오에서 기록 유실과 캘린더 중복 생성 같은 핵심 결함이 해결되어야 함 |

2주 개인 검증은 사용 편의와 부담을 확인하는 단계로 운영한다. 장기적인 루틴 유지 여부는 후속 4~8주 사용을 통해 관찰하고, 다른 사용자에 대한 효과는 별도 검증한다.

iOS 첫 버전의 실사용 검증을 마친 뒤 다음 단계로 Mac 앱과 iPhone 및 Mac 간 데이터 동기화를 진행한다. iPhone에서 축적한 계획, 실행 기록과 메모를 이어서 사용할 수 있도록 이전과 동기화 방식을 함께 설계한다. 분량 조정 제안, 캘린더에서 앱으로의 변경 반영, 위젯 등 추가 기능은 실제 사용에서 확인한 필요에 따라 별도로 우선순위를 정한다. 이 앱이 만들고자 하는 가치는 자신의 생활에 맞는 행동을 선택하고, 쉬었다가도 다시 이어갈 수 있다는 감각이다.
