# ADR 0003: 수행일별 기록과 주간 메모

상태: 채택 · 2026-10-20 · 관련 이슈 #10 · 기획 1.3

## 문제와 결정

완료 장부는 계획 날짜나 완료 입력 시각이 아닌 `performedOn`으로 묶어야 한다. 메모는 기록이 없는 주에도 작성할 수 있고, 수행일 정정이나 빠른 주 이동으로 다른 주에 저장되면 안 된다. 기존 occurrence는 현재 계획 날짜만 가지므로 과거 이동을 추측해 표시할 수 없다.

기존 기능별 폴더와 값 snapshot 조회를 재사용한다. `RecordsStore`가 별도 context에서 선택 주의 완료 기록과 메모를 읽고 메모 저장을 확정한다. 화면에 모델을 직접 편집시키거나 별도 저장 프레임워크를 추가하지 않는다. 기존 `CompletionSheet`와 실행 명령을 그대로 사용하며 recorder 변경 알림·화면 복귀 때 집계를 다시 읽는다.

## 저장과 이전

V4는 V3의 영속 모델을 그대로 재사용하고 두 모델만 추가한다.

- `WeeklyMemo`: 월요일 LocalDate key가 고유한 주별 본문. 공백·줄바꿈·빈 본문을 그대로 저장한다. 메모 조회만으로 모델을 만들지 않는다.
- `OccurrenceDateMove`: 고유 occurrence ID와 실제 첫 날짜 이동의 출발·도착 날짜. `PlanWriter.move/replan`에서 날짜가 달라지는 경우에만 계획과 같은 transaction에서 저장한다. 복원하며 날짜를 바꾸는 경우도 같은 경계를 사용한다. 한 번 저장한 근거는 이후 원래 날짜로 돌아가도 보존한다.

이동 근거가 없는 기존 데이터는 이동 여부 미확인이다. 수행일과 계획일의 차이, 수정시각이나 실행 구간으로 이동을 복원하지 않는다. 새 회차마다 false 행을 추가하거나 이전 자료를 backfill하지 않는다. 시간만 바꾸기·수행일 정정·완료 취소는 이동 근거를 만들지 않는다. 화면은 저장된 근거가 있는 경우에만 ‘날짜를 옮겨 마침’을 표시한다. 상세 변경 이력 화면은 범위 밖이다.

V1–V3의 영속 정의는 동결한다. migration 목록과 현재 container의 schema만 확장하고 lightweight V3→V4 이전을 사용한다. 실제 디스크 V1/V2/V3에서 이전·재열기로 ID, 날짜, snapshot, interval, 수동 시간 경계와 실행 상태를 검증한다. 실패를 빈 메모리 저장소로 숨기지 않는다.

## 집계와 시간

월~일 범위의 `performedOn`과 completed 상태를 함께 확인하고 occurrence ID당 한 번만 집계한다. 수행일 정정은 이전/새 주를 다시 조회하면 반영되며 메모와 계획은 이동하지 않는다. 완료 취소는 장부에서 빠지고 재완료는 기존 실행 명령이 새로 캡처한 수행일을 따른다.

루틴별 횟수는 routine ID로 묶고 해당 주의 완료 snapshot 이름을 사용한다. 과거 행의 이름은 루틴 원본 수정·보관으로 바꾸지 않는다. 동명이지만 ID가 다른 루틴은 합치지 않는다. 장부 → 실천 횟수 → 선택적 시간 → 자유 메모 순서를 유지한다.

시간은 기존 `RecordedDuration`을 사용한다. 확정 `seconds`만 합산하며 불확실 기록의 `knownSeconds`는 전체 합계에 넣지 않는다. 미기록·확정 0·1분 미만·확인 필요를 구분한다. 확정 시간이 하나도 없으면 합계는 생략하며, 혼합 자료에는 미기록/확인 필요 상태를 보조 표시한다. Double 합계가 유한 범위를 넘으면 합계를 확정하지 않고 그 상태를 표시하되 장부는 유지한다. 예상 시간을 실제 시간으로 대입하지 않는다.

## 메모 초안과 탐색

`AppTabs`가 소유한 `WeeklyMemoCoordinator`는 주별 초안과 저장 결과를 앱 수명 동안 유지한다. 입력 후 500ms debounce를 사용하고, 고정된 주키·입력 세대를 캡처해 취소되거나 오래된 작업이 새 주의 본문을 저장하지 못하게 한다. 주 이동, 메모 focus 해제, 기록 탭 이탈, scene 비활성화에서 최신 초안을 동기 flush한다.

저장 실패 시 그 주의 본문과 실패 상태를 유지하고 ‘다시 저장’을 제공한다. 저장 성공 전에는 저장됐다고 표시하지 않으며, 조회가 실패 초안을 덮어쓰지 않는다. 다른 주로 이동하거나 메모 없이 계획하는 동작은 허용한다. debounce 전 강제 종료 등 저장 기회가 없는 종료까지 미저장 입력의 영속 복원을 보장하지 않는다.

주간 계획은 대상 주의 직전 주 메모를 루틴 선택 앞에서 읽기 참고로 표시한다. 공란은 생략한다. 메모 초안이 저장 실패 상태라면 미저장임을 표시하고 재시도할 수 있으며 계획 진행을 막지 않는다. 별도 회고 알림·분량 제한·필수 질문은 추가하지 않는다.

Records의 ‘지난 계획 보기’는 선택한 기록 주의 agenda를 연다. ‘다음 주 계획’은 현재 현지 날짜 기준 다음 주를 명시해 열며, 과거 기록 주를 보고 있어도 과거 주에 새 계획을 만들지 않는다. `WeekRequest`에 호출자를 구분해 계획 취소는 Records로 복귀한다. 기존 Today 취소, 일반 탭의 상세 보존, 명시 agenda 요청의 목록 복귀와 타이머 불변 계약을 유지한다.

## 검증과 남은 범위

실제 검증 명령·환경·결과와 최신 head의 독립 Codex/Copilot 리뷰는 이슈 #10과 구현 PR에 기록한다. 2026-10-21 Xcode 26.6 / iPhone 15 Pro Simulator iOS 26.5에서 단위 전체 44개가 통과했다. 실제 V1/V2/V3 디스크 이전·재열기, 수행일 주 경계·실패·완료 취소/재완료, 시간 상태, 메모의 주 분리·실패·재시도·이동 근거 원자성을 포함한다. 리뷰에서 발견한 계획 메모 오류 표시를 보완한 뒤 메모 단위 4개와 새 네이티브 UI 2개를 재검증해 모두 통과했다. 입력 세대·debounce 경쟁은 단위 테스트, 실제 focus·주·탭·scene 이동·재실행과 계획 복귀는 UI 테스트로 구분한다. 기존 #30 네이티브 회귀 2개도 통과했으며, 최신 전체 CI와 리뷰는 구현 PR의 별도 병합 조건이다.
