# 한 주 iOS 앱 개발 인계

## 목표와 현재 상태

이 문서는 별도 Codex 개발 세션이 대화 내역 없이도 작업을 이어갈 수 있도록 제공합니다. 사용자는 디자인을 별도 에이전트에 맡기고 주 에이전트가 감독한 뒤, 개발은 별도 세션에서 진행하도록 요청했습니다.

현재 산출물은 디자인 명세, 토큰, 브라우저 프리뷰입니다. 네이티브 iOS 앱, Xcode 프로젝트, 실제 알림과 캘린더 연동은 아직 구현하지 않았습니다. 에이전트의 디자인 검토와 사용자의 최종 디자인 선택은 구분해야 합니다.

디자인 감독 검토는 완료했습니다. 8개 화면의 320pt·다크·큰 글자 배치와 조작 영역, 주요 계획·실행·메모 흐름을 브라우저에서 확인했으며 구체적인 결과와 미검증 항목은 `docs/design-review.md`에 있습니다. HTML은 고정된 예시 날짜와 localStorage를 사용하는 설계 참고 자료입니다.

## 먼저 읽을 자료

1. `docs/product-plan.md`: 확정된 iOS 우선 기획의 로컬 사본.
2. `design/reference/user-design-brief.txt`: 사용자가 제시한 전체 디자인 요구.
3. `design/01-direction.md`와 `design/02-foundations.md`: 제품 태도와 시각 규칙.
4. `design/tokens.json`: 구현에서 사용할 토큰 값의 기준.
5. `design/03-components.md`와 `design/04-screens.md`: 컴포넌트 및 화면 계약.
6. `design/05-swiftui-handoff.md`: SwiftUI 구성과 상태 연결 지침.
7. `docs/design-review.md`: 감독 검토 결과, 수정 사항, 미검증 영역.
8. `design/preview/index.html`: 디자인과 로컬 상호작용 예시.
9. `design/06-art-direction-review.md`: 스킬 적용 후 방향 비교, 화면별 고유 요소, HIG 원칙 검토.
10. `design/07-experience-contract.md`: 네 스킬의 책임, 상태·탐색·모션·접근성·시뮬레이터 검증 계약.

이후 사용자가 수정한 요구가 있으면 이를 우선합니다. 문서와 프리뷰 사이에 충돌을 발견하면 조용히 임의 해석하지 말고, 해당 항목을 구체적으로 정리해 확인하거나 근거 있는 수정안을 제시합니다.

## 사용자가 지정한 스킬과 판단 순서

이 프로젝트의 `.agents/skills/` 아래 설치본을 읽고 역할별로 적용합니다.

- `swiftui-design-skill/SKILL.md`: 아트 디렉션, 위계, 서체, 간격, 화면 구성.
- `apple-design/SKILL.md`: HIG와 네이티브 탐색·입력·취소의 제약.
- `swiftui-pro/SKILL.md`: SwiftUI 구현, 데이터 흐름, 동시성, 유지보수 품질.
- `design-swiftui-interfaces/SKILL.md`: 인터랙션 안정성, 모션, 접근성 대안, 시각 QA.

우선순위는 **제품 철학 → 아트 디렉션 → 시각 위계·고유 정체성 → 네이티브 iOS 인터랙션 → 구현 정확성 → 시뮬레이터 시각 QA**입니다. 스킬별 기본 스타일을 절충해 평범한 중간안으로 바꾸지 않습니다. `standard` 프로필 안에서 기존 콘텐츠 구도를 유지하고, 시스템 탐색·조작의 의미와 접근성은 보장합니다.

새 앱 기본 착수안은 `swiftui-pro`의 iOS 26 / Swift 6.2 이상입니다. 아직 배포타깃 설정은 없으므로 실제 지원 기기와 Xcode/SDK를 확인해 확정합니다. 기존 macOS용 Swift 6.1.2 확인 결과를 iOS 빌드 환경으로 취급하지 않습니다.

## 유지할 제품 결정

- iPhone용 iOS 앱부터 개발합니다. Mac 앱 및 CloudKit 기반 앱 데이터 동기화는 후속 단계입니다.
- SwiftUI, SwiftData, UserNotifications, EventKit을 기본 구성으로 검토합니다. 별도 서버나 외부 계정 시스템을 추가하지 않습니다.
- 한 주는 월요일부터 일요일까지입니다. 일요일에는 다음 주 계획을 고릅니다.
- 루틴 원본과 주별 실행 항목을 분리합니다. 루틴 수정으로 과거 실행 기록이 바뀌면 안 됩니다.
- 시작·일시 정지·이어 하기·완료와 타이머 없는 바로 완료를 구분합니다. 시간 미기록을 0분으로 취급하지 않습니다. 실제 기록이 1분 미만이면 ‘1분 미만 기록’으로 표시합니다.
- 날짜 이동, 이번 주 건너뛰기, 다음 주 재선택을 지원합니다. 미완료 자동 누적과 재촉 알림은 기본으로 넣지 않습니다.
- 캘린더는 앱에서 Apple 캘린더로 반영합니다. 회차별 연결을 보관하고 생성·변경·제외 시 중복과 오래된 알림을 방지합니다.
- 캘린더 권한이 없어도 앱의 기본 기능을 사용할 수 있어야 합니다. 외부에서 바뀐 캘린더 일정을 조용히 덮어쓰지 않습니다.
- 회고는 선택적인 자유 메모 한 장입니다. 자동 저장하며 회고를 건너뛰어도 다음 계획으로 진행합니다.
- 성취 화면은 실제로 해낸 일과 기록한 시간을 보여줍니다. 연속 일수, XP, 원형 완료율을 넣지 않습니다.

## 구현 순서

1. 개발 환경과 최소 지원 iOS 버전을 확인하고 프로젝트 구성을 정합니다.
2. 색상 Assets, Typography, Spacing, Radius, Motion을 토큰에서 구현합니다.
3. 버튼, 루틴 행, 요일 선택, 상태 표시 같은 실제로 재사용되는 컴포넌트를 만듭니다.
4. 목 데이터로 오늘·이번 주·루틴함·기록·설정과 관련 시트를 조립합니다.
5. SwiftData 모델과 저장을 연결합니다. 앱 재시작, 메모 자동 저장, 잘못 누른 완료 취소를 검증합니다.
6. UserNotifications와 EventKit을 실제 기기에서 연결합니다. 권한, 오프라인, 일정 변경, 중복을 검증합니다.
7. 작은 화면·큰 글자·다크 모드·VoiceOver·Reduce Motion을 네이티브에서 검증합니다.
8. 집안일과 공부로 2주 실사용하고 사용 부담과 실행 편의를 조정합니다.

프리뷰 HTML을 WebView로 포장하거나 CSS 구조를 SwiftUI로 기계적으로 옮기지 않습니다. 네이티브 NavigationStack, TabView, Sheet, DatePicker와 의미 기반 접근성을 사용합니다. 시각 토큰은 유지하되 운영체제의 기본 동작과 접근성에 맞게 구현합니다.

## 개발 환경 확인 기록

2026년 10월 4일 디자인 작업 중 확인한 결과입니다.

- 활성 개발 경로: `/Library/Developer/CommandLineTools`.
- Swift: Apple Swift 6.1.2, macOS 대상.
- `/Applications`에서 `Xcode*.app` 번들을 찾지 못했습니다.
- 네 스킬 적용 재검토 시 `xcodebuild -version`은 활성 CommandLineTools 경로 때문에 실패했고 `xcrun simctl list devices available`도 simctl을 찾지 못했습니다.
- 설치된 스킬의 정적 검사 스크립트는 Swift 파일이 없어 종료 코드 2를 반환했습니다. 오류 0건 또는 native 통과로 집계하지 않습니다.
- 이 결과만으로 다른 위치의 Xcode 설치 여부를 단정하지 않습니다. 개발 세션에서 전체 Xcode와 iOS SDK 및 Simulator 사용 가능 여부를 먼저 확인해야 합니다.
- 이 디자인 작업에서는 Xcode 설치, 도구 경로 변경, 서명 설정, 네이티브 앱 빌드를 수행하지 않았습니다.
