# 한 주 — Design Direction

2026-10-04 · Phase 1 · iPhone MVP 디자인 기준

「한 주」는 이번 주에 할 일을 고르고, 생활이 달라지면 계획도 바꾸는 도구다. 기록은 행동의 흔적이며 평가표가 아니다. 화면은 다음 행동을 분명하게 제안하되 실행·메모·캘린더 사용을 강요하지 않는다. 기획 기준은 `docs/product-plan.md`, 원본 요구는 `design/reference/user-design-brief.txt`다.

## 제품 태도

오늘 할 일은 읽기 쉽고 시작하기 쉬워야 한다. 끝낸 일은 눈에 남기되 현재 행동보다 조용하게 표현한다. 예상 시간은 계획을 가늠하는 정보이고, 실제 기록 시간은 사용자가 남긴 사실이다. 두 값을 섞지 않는다. 날짜를 옮기거나 건너뛰어도 붉은 상태, 점수 하락, 밀린 일 배지가 생기지 않는다.

## Brand attributes

| 성격 | 의미 | UI 표현 | 금지 표현 |
| --- | --- | --- | --- |
| 차분함 · Calm | 시작 앞의 긴장을 낮춘다 | 종이색 배경, 정렬된 행, 조용한 보조 텍스트 | 긴급 배너, 일상 상태의 경고색 |
| 유연함 · Flexible | 계획 수정도 정상적인 사용이다 | 각 예정 항목의 ‘옮기기’, 주간 선택의 자유 | 자동 이월, 이유 입력 강제 |
| 사람다움 · Human | 일상 언어로 선택을 설명한다 | ‘이미 했어요’, ‘시간 미기록’, 짧은 시작 행동 | 템플릿 인사, 감정적인 응원 문단 |
| 정밀함 · Precise | 날짜·시간·저장 상태를 믿을 수 있다 | 명시적 주간 범위, 예상/기록 구분, 변경 결과 | 모호한 ‘동기화 완료’, 미기록=0분 |
| 절제 · Quiet | 필요한 신호에만 시선을 준다 | 강조색 한 가지, 텍스트 버튼, 최소 심볼 | 장식 아이콘, 그림, 색상 분류 남용 |

## 선택한 시각 언어 — 정돈한 생활의 페이지

**Editorial utility + soft precision.** 흰 카드들을 쌓는 대신 화면마다 다른 정보 구조를 사용한다. 상단 제목, 섹션 표제, 수평 구분선과 일정한 들여쓰기가 페이지의 골격이다. SF 계열 시스템 서체의 크기와 굵기만으로 날짜와 루틴 이름, 부가정보를 구분한다. 한글 본문은 17pt, 행 높이에 여유를 둔다.

바탕은 약한 따뜻함이 있는 `background`, 본문은 녹색 기운을 아주 조금 가진 짙은 중성색이다. 강조색은 **차분한 숲빛 `accent`**로 결정했다. 생활과 가까운 인상이면서 작은 버튼·선택 상태에서도 충분한 대비를 확보한다. sage는 큰 배경으로 쓸 경우 대비가 약해져 `accentSubtle`에만 제한한다. olive의 노란 기운은 일시 정지·주의와 혼동하기 쉬워 주색에서 제외했다. 따뜻한 청색은 캘린더 보조 상태에만 사용한다.

- 오늘: 날짜 → 실행 중인 한 항목 → 예정 행 → 완료 행. 한 개의 활성 면만 허용.
- 이번 주: 날짜 범위 → 일렬 요일 탐색 → 선택 날짜의 세로 목록. 7열 시간표를 복제하지 않는다.
- 루틴함: 분류별 목록. 이름과 시간·기본 횟수를 같은 정렬축에 둔다.
- 기록: 날짜별 실행 장부 + 자유 메모. 통계 대시보드를 만들지 않는다.
- 설정: 시스템 방식의 구분된 기능 목록.
- 편집: 이름부터 쓰는 가벼운 시트. 세부 항목은 순차 공개한다.
- 일정 이동: 원래 날짜와 새 날짜를 연결하는 선택 시트.
- 실행: 루틴명·첫 행동·기록 시간·제어만 남긴 집중 화면.

## 금지 패턴

강한 gradient, 콘텐츠의 장식적 유리·glow·neon, 카드 안의 카드, 과한 둥근 모서리와 그림자, 원형 완료율, streak/XP/레벨, 미완료 수 배지, 3열 지표 dashboard, 모든 행의 임의 아이콘, 억지 감성 문구, 의미 없는 그림, Mac용 레이아웃의 축소판을 사용하지 않는다. 완료 여부와 category를 색만으로 표현하지 않는다. 실패·오류 색은 데이터 저장 실패나 실제 삭제처럼 복구가 필요한 경우에만 쓴다. 권한 미허용은 중립적으로 표시한다.

## 판단 기준

1. 색과 면을 제거해도 제목·행·정렬만으로 지금 할 행동을 찾는가?
2. 화면 한 곳에만 주된 행동이 있는가? 실행 중이면 ‘완료’가 주 행동이다.
3. 모든 장식과 문장은 구체적인 판단이나 행동을 돕는가?
4. 못 한 일, 건너뛴 일, 기록하지 않은 시간이 실패처럼 보이지 않는가?
5. 날짜 이동·직접 완료·선택하지 않음을 짧은 경로로 수행하는가?
6. 320pt와 큰 글자에서 텍스트를 자르지 않고 세로로 확장하는가?
7. 완료·건너뛰기·캘린더 반영을 서로 다른 상태로 전달하는가?

## 작업 범위

이 산출물은 디자인 명세와 브라우저 시뮬레이션이다. 네이티브 SwiftUI 앱, Xcode 프로젝트, 실제 UserNotifications/EventKit 연결은 후속 개발 세션의 범위다. SwiftData 로컬 저장을 전제로 하며 앱 데이터의 CloudKit 동기화와 Mac 화면은 후속 단계다.

## 스킬 재검토로 확정한 아트디렉션

`swiftui-design-skill`과 `apple-design`으로 재검토한 결과, **정돈한 생활의 페이지**를 유지한다. 대안인 시간축 중심의 촘촘한 agenda는 시간을 정하지 않은 일까지 시간표처럼 보이게 하고, 한 가지씩만 보여주는 집중 화면은 오늘의 분량과 주간 조정을 찾기 어렵게 한다. 현재안은 이름·날짜·시작 행동을 같은 흐름에서 읽게 하면서 실행 화면에만 집중 구도를 허용한다. 구조별 비교와 8화면 signature는 `06-art-direction-review.md`에 기록한다.

판단 순서는 **제품 철학 → 아트디렉션 → 시각 위계·고유 정체성 → iOS 상호작용 → 구현 정확성 → 시뮬레이터 QA**다. 접근성은 이 순서에서 생략 가능한 취향이 아니라 읽기·조작을 위한 경계다. 대비나 입력 접근성을 낮춰 차분함을 만들지 않는다.

브랜드는 서체를 추가하거나 특수 애니메이션을 넣어 구분하지 않는다. ‘시작할 한 가지와 남은 목록’, ‘월–일을 고른 뒤 읽는 하루’, ‘날짜별 실제 행동과 자유 메모’의 구도가 브랜드의 핵심이다. Settings는 기능의 정렬과 권한 설명으로, RoutineEditor는 이름부터 쓰는 순서로 성격을 드러낸다. signature는 화면마다 필요한 구조적 세부 하나를 정교하게 다듬는다는 뜻이며 장식 추가의 의무가 아니다.

스킬의 세리프 제목·두 폰트·다섯 브랜드색·8pt 격자·Settings 탭 제외는 이 제품의 원본 요구를 대체하지 않는다. 한국어 system type, 한 가지 primary accent, 4pt 토큰, 확정된 다섯 목적지를 유지한다. 외부 브랜드가 없는 가칭 제품이므로 동일 이름의 외부 로고나 브랜드 가이드를 수집하지 않는다. 이 문서와 Foundations가 해당 제품의 브랜드 명세다.

사용자가 권한을 허용하지 않은 상태는 오류가 아니다. ‘허용 안 됨’과 기능 사용 범위를 중립적으로 설명한다. destructive는 저장 실패나 실제 삭제처럼 처리 결과에 복구가 필요한 상태에만 사용한다.
