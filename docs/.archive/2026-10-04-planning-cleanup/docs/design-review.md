# 한 주 디자인 감독 검토

검토 기준일: 2026년 10월 4일. 현재 상태: 디자인 명세와 로컬 프리뷰 감독 검토 완료. 후속 iOS 개발에 인계 가능한 초안이며, 사용자의 최종 시각 디자인 승인을 뜻하지 않습니다.

## 검토 범위

사용자 디자인 지침, iOS 우선 기획, 시각 토큰, 컴포넌트 명세, 8개 화면, 주요 상호작용, 개발 인계의 일관성을 검토합니다.

## 통과 기준

- 부담을 주는 미완료 경고, 스트릭, 완료율 평가, 반복 재촉이 없다.
- 정보는 위치, 글자 크기, 무게, 간격으로 구분되며 카드 배경과 색에 의존하지 않는다.
- 오늘·주간·루틴함·기록·설정의 정보 구조가 각각 목적에 맞는다.
- 타이머 없이 완료한 일을 실제 시간 0분으로 만들지 않는다.
- 일정 이동과 건너뛰기, 회고 미작성, 권한 거절에서도 실행 흐름이 이어진다.
- light/dark 토큰, 최소 44pt 터치 영역, 색 외의 상태 표현, 큰 글자와 Reduce Motion 대응을 명세한다.
- 프리뷰와 SwiftUI 인계서가 같은 토큰과 상태 모델을 사용한다.
- 실제 앱과 디자인 시뮬레이션의 검증 범위를 명확히 구분한다.

## 참고 기준

- [Apple UI Design Dos and Don’ts](https://developer.apple.com/design/tips/): 터치 영역, 정렬, 대비, 읽기 쉬운 크기.
- [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout): 안전 영역과 글자 크기 변화에 적응하는 배치.

## 검토 기록

### 시각 방향과 기초 토큰

디자인 에이전트가 Phase 1과 Phase 2를 먼저 작성한 뒤 감독 검토를 거쳐 화면 제작으로 진행했습니다. 방향은 따뜻한 중성색과 숲빛 강조색, 글자와 정렬 중심의 목록 구성입니다. 실행 중인 한 항목 외에는 카드 면 사용을 제한하고, 오늘·주간·루틴함·기록의 정보 구조를 다르게 구성합니다.

주 에이전트가 foundations의 실제 Hex 값을 별도로 읽고 sRGB 상대휘도 대비를 계산했습니다. 디자이너가 제출할 계산 결과와 독립적으로 확인한 값입니다.

| 검토 항목 | Light | Dark | 판정 |
| --- | ---: | ---: | --- |
| 일반 텍스트 및 상태 글자와 3개 중성 배경의 최소 대비 | 4.635:1 | 5.303:1 | 4.5:1 이상 |
| 주 버튼 전경과 accent 배경 | 6.466:1 | 8.937:1 | 4.5:1 이상 |
| 의미 있는 control 경계와 중성 배경의 최소 대비 | 3.268:1 | 3.135:1 | 3:1 이상 |
| 선택 및 활성 배경의 허용 텍스트 최소 대비 | 5.315:1 | 6.122:1 | 4.5:1 이상 |

장식적인 separator는 의미 있는 컨트롤 경계로 쓰지 않도록 명세했습니다. 이 계산은 불투명한 토큰 색상의 대비이며, 실제 프리뷰에서 임의 opacity나 다른 배경을 사용하면 별도 검토해야 합니다.

### 화면과 상호작용

주 에이전트가 Codex 브라우저에서 직접 조작했습니다. 검토 데이터는 마지막에 예시 초기화로 복원했습니다.

| 항목 | 직접 확인한 결과 |
| --- | --- |
| 8개 화면 | 오늘, 이번 주, 루틴함, 기록, 설정, 루틴 편집, 일정 옮기기, 실행 중의 정보 구조와 이동 경로 확인 |
| 320pt·다크·큰 글자 | 8개 화면 본문의 scrollWidth와 clientWidth가 모두 320px. 표시 중인 제품 버튼·입력·선택 영역 중 폭/높이 44px 미만 없음. 별도 실행 중 상태도 확인 |
| 긴 이름 | 320pt·큰 글자에서 긴 루틴 이름이 여러 줄로 확장되고 본문 가로 넘침 없음. 이름만 입력해 루틴 저장 가능 |
| 실행 기록 | 시작 → 일시 정지 → 재개 → 완료. 1분 미만 실행과 타이머 없이 완료를 각각 ‘1분 미만 기록’, ‘시간 미기록’으로 표시 |
| 날짜 이동 | 10월 4일 항목을 다음 주 10월 6일로 옮긴 뒤 해당 주·날짜에서 확인 |
| 건너뛰기 | ‘이번 주 건너뜀’ 표시, 남은 예상 시간에서 제외, 되돌리기 제공. 완료로 합산하지 않음 |
| 다음 주 계획 | 루틴 선택 → 기본 3회를 2회로 변경 → 2회차 목요일 배치 → 확정 → 월/목 계획 확인 |
| 주간 메모 | 입력 후 새로고침해 원문 복원 확인. 다음 주로 이동하면 별도 메모 표시 |
| 캘린더 | 권한 미허용 시 기본 기능 사용 안내, 부분 실패의 재시도, 외부 변경의 재반영/나중에 결정 경로 확인. 실제 OS 연결은 수행하지 않음 |
| 빈 상태·오류 | 오늘 빈 상태에서 계획 이동 경로 제공. 오류 예시에서 재시도 안내와 보존된 실행 상태 표시 |
| 브라우저 진단 | 검토 중 수집된 console warn/error 없음 |

390pt 기준 레이아웃과 주요 화면 스크린샷을 시각 검토했습니다. 위의 320pt 수치는 브라우저 CSS 픽셀 측정입니다. iOS의 실제 터치 판정이나 모든 Dynamic Type 크기·VoiceOver 조합의 통과를 뜻하지 않습니다. 큰 글자 검토 도구는 1.28배 시뮬레이션입니다.

### 감독 피드백으로 수정한 사항

- 화면의 임의 글자 굵기·크기·간격을 토큰에 연결. 실행 타이머도 큰 글자 설정에 반응하도록 수정.
- 요일 선택과 체크 버튼의 실제 조작 영역을 44pt 이상으로 확대. 좁은 화면에서는 선택한 요일이 보이도록 날짜 strip 내부만 스크롤.
- ‘오늘 함께 정한 일’을 ‘오늘 정한 일’로, 예상 시간 합계를 ‘남은 예상’으로 명확화.
- 1분 미만의 실제 기록을 0분으로 표시하지 않도록 공통 표기 규칙 추가.
- 메모를 주별로 분리하고 캘린더 상태 전환용 도구를 제품 화면 밖으로 이동.
- 고정 390pt 기기 라벨을 반응형 프리뷰에 맞는 일반 라벨로 수정.

### 산출물 정합

사용자 원본과 보관한 디자인 지침의 바이트 일치, JSON 토큰과 HTML에 포함된 토큰의 구조 일치, 외부 HTTP 리소스 참조 없음, 컴포넌트 요구 33종의 명세 존재를 주 에이전트가 확인했습니다. 디자이너는 별도로 JavaScript 구문, 8화면×3상태의 24개 렌더 및 주요 상태 전환을 정적 환경에서 점검했습니다. 정적 점검은 위 브라우저 조작 검토와 구분합니다.

### 후속 개발에서 확인할 항목

- 실제 SwiftUI 화면과 시스템 TabView·NavigationStack·Sheet·DatePicker의 동작 및 접근성.
- SwiftData 저장 실패·재시작 복원, 메모 자동 저장과 앱 전환 시 저장, 실행 시간의 백그라운드 복원.
- 알림 권한과 예약·취소·재예약, Calendar 연결 ID 유지·중복 방지·부분 실패·외부 변경 처리.
- iPhone의 VoiceOver, Dynamic Type 접근성 크기, Reduce Motion, 안전 영역과 키보드 가림.
- 배포할 최소 iOS 버전과 실제 Xcode/iOS SDK 사용 가능 여부.

프리뷰는 2026년 10월 4일을 기준으로 한 예시와 브라우저 localStorage를 사용합니다. 실제 날짜·OS 권한·서비스 장애를 구현한 앱으로 취급하지 않습니다. 완성된 네이티브 앱이나 전체 제품 QA의 통과 판정은 이번 산출물 범위가 아닙니다.

## 네 스킬 적용 후 추가 검토

사용자가 지정한 네 스킬을 역할별로 적용했습니다. 디자인 에이전트는 `swiftui-design-skill`과 `apple-design`으로 구조·시각 위계·HIG 8원칙을 다시 검토했고, 주 에이전트는 `swiftui-pro`와 `design-swiftui-interfaces`로 구현 계약·상태 소유·접근성·모션·검증 게이트를 보완했습니다. 파일 경로와 책임은 [경험 계약](../design/07-experience-contract.md), 구조 비교와 HIG 판정은 [아트 디렉션 검토](../design/06-art-direction-review.md)에 있습니다.

현재의 아트 디렉션을 유지합니다. 스킬 예시의 세리프·8pt·재질 권고로 기존 한국어 시스템 서체·4pt 토큰·불투명 콘텐츠 배경을 바꾸지 않았습니다. 시스템 탐색 재질은 OS 컴포넌트가 담당하도록 경계를 명확히 했습니다.

| 발견 | 수정과 실제 확인 |
| --- | --- |
| Today에서 Reschedule 취소 시 Week로 이동 | 수정 전 직접 재현. 호출한 화면과 스크롤·제어 정보를 보존하도록 변경. Today/Week 각각에서 취소 후 화면·선택 날짜·호출 버튼 focus 복원을 확인 |
| Running push 명세와 탭 숨김 프리뷰 불일치 | Running에 5탭을 유지하고 Today를 선택 상태로 표시. Settings 왕복 후 실행 시간이 계속 유지됨을 확인하고 테스트 실행은 일시 정지 |

변경된 Running 화면은 320px·다크·큰 글자(1.28배)에서 다시 확인했습니다. 본문 clientWidth/scrollWidth 모두 320px, 표시되는 제품 제어 중 44px 미만 없음, 완료 버튼과 탭 배치가 전체 페이지 캡처에서 보이는 것을 확인했습니다. 기존 `tokens.json`과 프리뷰의 토큰 사본도 일치합니다. 기존 예시 데이터 전체를 초기화하지 않았습니다.

이번 명세에는 편집 draft 취소 확인, 반복 확정 command의 중복 방지, 접근성 설정별 실제 동작, 시뮬레이터 연타·중단·회전·background 검증 조건을 추가했습니다. 이는 native 개발 계약이며 웹 프리뷰에서 모두 구현·검증했다고 주장하지 않습니다.

환경 재확인 결과 Swift 소스 0개, `xcodebuild`는 활성 CommandLineTools 경로에서 실행 불가, `simctl`은 발견되지 않았습니다. 설치된 스킬 정적 감사는 ‘Swift 파일 없음’으로 종료 코드 2를 반환했습니다. 따라서 native build/runtime/보조기술/Instruments 결과는 미검증이며 Apple Fidelity 점수도 산정하지 않습니다. 디자인 인계에 대한 검토 완료와 네이티브 앱 출시 판정은 구분합니다.
