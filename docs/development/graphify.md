# 병합 후 Graphify 운영

Graphify는 확정된 코드와 문서의 탐색을 돕는 지식 그래프다. 제품 명세와 소스 코드를 대체하지 않는다.

## 실행 시점과 담당

- 개발 PR이 **main에 병합된 뒤** 개발총괄이 생성 또는 갱신을 담당한다. 아직 병합하지 않은 변경은 포함하지 않는다.
- 커밋 훅, 작업 브랜치 CI, watch에서 자동 생성하지 않는다. 여러 PR이 연속 병합되면 하나의 최신 main SHA로 묶어 처리할 수 있다.
- 개발 중에는 마지막 main 그래프를 읽기 전용으로 조회할 수 있다. 생성 기준 SHA 이후의 변경은 원본 diff로 확인한다. 그래프가 없으면 파일 검색을 사용한다.
- `graphify-out/`만 갱신한 PR은 다시 graphify를 실행하는 계기가 아니다. 결과물을 입력에도 포함하지 않아 갱신 루프를 막는다.

## 입력과 AI 사용

입력은 main에 추적된 제품 소스·테스트·현재 기획·디자인·개발 문서다. `docs/.archive/`, `.agents/skills/`, `.git/`, 빌드·캐시·의존성 산출물, `graphify-out/`, 비밀정보·개인 데이터는 제외한다. 탐지 목록을 확인하고 제외 경로가 실제 입력에 들어가지 않도록 필터링한다. 무시 파일 설정만 믿지 않는다.

코드 구조 추출은 graphify가 처리한다. 의미 추출과 커뮤니티 라벨링은 **현재 사용 중인 AI 도구의 세션 또는 동일 도구의 하위 에이전트**가 한다. 지금의 도구는 Codex다. 실행 시 실제 도구·모델 정보를 기록하고, 도구를 바꾸면 해당 실행에 새 도구를 기록한다.

설정되어 있는 API 키가 있다는 이유로 Gemini 등 외부 LLM 백엔드로 전환하지 않는다. 별도 API 키를 요구하지 않는다. 스킬의 자동 백엔드 선택과 충돌하면 이 프로젝트 규칙을 우선하고 현재 세션이 의미 추출·라벨 JSON을 작성하는 경로를 사용한다. 전역 환경이나 사용자 키 설정을 수정하지 않는다.

라벨은 묶음의 실제 노드와 출처를 읽고 2~5단어의 구체적인 한국어 이름으로 작성한다. 예: `주간 계획 배치`, `실행 시간 기록`, `캘린더 일정 반영`. 재클러스터링하면 커뮤니티 ID가 바뀔 수 있으므로 ID만 보고 과거 이름을 복사하지 않는다. 근거 없이 레이어나 관계를 만들지 않는다. 원본 Swift 심볼은 유지하고 EXTRACTED/INFERRED/AMBIGUOUS를 구분한다. 미확인 모델명·토큰 사용량은 추정하지 않고 알 수 없음으로 기록한다.

## 실행 절차

1. 병합된 PR/이슈, main의 기준 SHA, 담당자를 후속 작업으로 기록한다. 설치된 graphify 스킬과 버전을 확인한다. 아래 `/graphify` 표기는 AI 도구에 전달하는 스킬 요청이며 셸 명령이 아니다.
2. main의 해당 SHA를 별도 깨끗한 checkout/worktree로 고정하고 거기서 분석한다. detached HEAD 읽기 전용 분석은 허용한다. 작업 중 파일을 분석용으로 main에 합치지 않는다.
3. 입력 목록과 제외 범위를 확인한다. 최초는 `/graphify .`, 이후는 `/graphify . --update`에 해당하는 스킬 절차를 수행하되 위의 시점·입력·AI 규칙을 명시한다. 증분 캐시가 없으면 전체 생성한다.
4. 그래프 무결성, 소스 경로, 누락 파일, 고립/끊긴 관계, 입력 삭제로 인한 축소를 확인한다. 결과가 비거나 불완전하면 기존 정상 결과를 덮어쓰지 않는다. 축소 보호를 우회하기 전에 실제 소스 삭제와 입력 범위 변경을 확인한다.
5. 현재 AI 세션에서 커뮤니티를 라벨링하고 `GRAPH_REPORT.md`, `graph.json`의 `community_name`, `.graphify_labels.json`의 이름이 일치하도록 재생성한다. HTML은 필요한 경우 로컬에서 생성해 확인한다.
6. 아래 메타데이터와 최종 결과만 별도의 `codex/docs/<관련이슈>-graph-update` 브랜치로 옮겨 PR을 만든다. 대표 이슈는 원래 개발 이슈를 재사용할 수 있으며 `Refs #번호`로 연결한다. 여러 변경을 묶으면 관련 이슈를 모두 적는다.
7. 리뷰 후 결과 PR을 병합하고 후속 작업에 완료를 기록한다. 이 PR의 SHA와 분석 대상인 main의 SHA는 서로 다르다. 그래프는 메타데이터의 분석 대상 SHA를 설명한다.

초기화·업데이트·라벨 재출력의 구체적인 API는 설치된 스킬의 버전에 따른다. 스킬이 없으면 설치 여부를 해결하거나 후속 작업을 대기로 기록한다. 성공하지 않은 그래프를 최신이라고 표시하지 않는다.

## 결과와 출처 보관

다음 파일만 Git으로 공유한다. 캐시·임시 추출물·개인 경로·HTML은 로컬에 둔다.

```text
graphify-out/graph.json
graphify-out/GRAPH_REPORT.md
graphify-out/.graphify_labels.json
graphify-out/provenance.json
```

`provenance.json`은 실행 세션이 작성한다. 아래는 형식 예시이며 실제 생성 시 모든 placeholder를 실제 값으로 채운다.

```json
{
  "source_branch": "main",
  "source_commit": "<분석한 main의 전체 SHA>",
  "source_issues": [42],
  "source_prs": [43],
  "generated_at": "<시간대 포함 ISO-8601>",
  "graphify_version": "<실행 버전>",
  "ai_tool": "Codex",
  "ai_model": null,
  "mode": "full",
  "excluded_paths": ["docs/.archive/", ".agents/skills/", ".git/", "graphify-out/"],
  "health": "ok",
  "warnings": []
}
```

저장하는 경로는 저장소 상대 경로로 통일한다. 생성된 보고서에도 사용자 홈 절대 경로가 남지 않게 확인한다. 증분 생성이면 `mode`는 `incremental`, 무결성 경고가 있으면 `health`는 `warning`과 실제 내용을 기록한다. 토큰 집계가 제공되지 않으면 0 비용으로 단정하지 않는다.

갱신 실패 시 기준 SHA·실패 단계·원인·재시도 담당을 후속 작업에 기록하고 기존 결과의 provenance를 유지한다. 그래프의 현재성은 source_commit으로 판단한다. 다음 개발 작업을 그래프 실패만으로 막지 않는다.
